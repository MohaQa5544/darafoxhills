# نظام تقييم أداء المقاولين والاستشاريين — الإدارة العامة للأوقاف

مجلد مشروع «66 - 2610 تقييم المقاولين والاستشاريين». البرنامج اسمه «سجل الأداء»، ويعمل بطريقتين من الكود نفسه:

1. **أوفلاين**: يُفتح `app/index.html` من مجلد دروب بوكس المشترك، والبيانات ملفات JSON في `data/` أو في المتصفح.
2. **سحابي (رابط على Vercel)**: الواجهة نفسها مع خادم في `app/api` و`app/lib`، وبيانات مشتركة لكل الفريق في متجر Vercel Blob خاص. عند فتح البرنامج من رابط يكتشف الخادم تلقائياً ولا تظهر شاشة اختيار مكان البيانات.

- الخطة الكاملة: https://claude.ai/artifact/9wPsxUonAoeDSsZQoKv3ak — ونسخة منها دون أسماء المستخدمين في `docs/plan.html`.

## محتوى المجلد
- `app/` — البرنامج: `index.html`، `boot.js`، `core.js`، `store.js` (مجلد / متصفح / سحابي)، `screens.js`، `eval.js`، `review.js`، `reports.js`، `settings.js`، `bank.js` (بنك الأسئلة والأوزان الافتراضية)، `texts.js` (نصوص الخطابات)، `logos.js`، `app.css`.
- `app/api/` — دوال Vercel: `rpc` (الدخول والبيانات)، `file` (المرفقات)، `health`، و`selftest` (فحص على المنصة لا يعمل إلا بمفتاح `SELFTEST_KEY`).
- `app/lib/` — منطق الخادم: `core.mjs` (الدخول، الصلاحيات، التخزين المتزامن، الاستيراد والتصدير)، `blob-store.mjs` (Vercel Blob)، `runtime.mjs` (التهيئة من متغيرات البيئة).
- `app/vercel.json` — رؤوس الأمان (CSP وغيرها) وإعدادات الدوال؛ `app/package.json` يثبّت إصدار `@vercel/blob`.
- `app/brand/` — خلفية الورق الرسمي الطولية، والخلفية العرضية للتقارير، والشعارات.
- `dev/` — خادم تطوير محلي (`server.mjs`) بمحرك تخزين يحاكي Vercel Blob (`fs-store.mjs`)، ومستخدمو اختبار (`seed.example.json`)، و`make-seed.mjs` لتحضير `SEED_USERS`.
- `test/` — `e2e.js` (الأوفلاين)، `e2e-cloud.js` (الواجهة السحابية كاملة في المتصفح)، `api-cloud.mjs` (اختبارات الخادم والأمان).

## النسخة السحابية: كيف تعمل
- **التخزين**: مستند واحد مضغوط `ev/db.json.gz` في متجر Blob خاص، يُكتب بشرط ETag (تزامن تفاؤلي) فلا تضيع تعديلات مستخدمَين متزامنين. الطلبات التي تصل معاً إلى نسخة الخادم نفسها تُجمع في كتابة واحدة. تعديل سجل قديم يُرفض برسالة «عدّل مستخدم آخر…» بدل الكتابة فوقه، وحفظ سجل حذفه غيرك يُرفض فلا يعود إلى الحياة. أرقام الخطابات يخصصها الخادم فلا تتكرر.
- **المرفقات**: ملفات خاصة في `ev/files/` حتى 4 ميجابايت للملف. الرفع لا يكتب فوق ملف موجود، وحذف المرفق يحذف ملفه. النسخة الموقعة من إخطار العقد وثيقة رسمية متاحة لكل موظفي الإدارة، أما مرفقات التقييمات فتتبع إعداد الرؤية.
- **النسخ الاحتياطي والتدقيق**: نسخة يومية تلقائية في `ev/backups/` تُحذف بعد 35 يوماً، وسجل التدقيق يُؤرشف في `ev/audit/` ويعود كاملاً في التصدير. بيئات المعاينة (Preview) تكتب تحت بادئة مستقلة `ev-preview/` فلا تمس بيانات الإنتاج.
- **الدخول**: كلمات المرور مجزأة PBKDF2 على الخادم ولا تصل إلى المتصفح، والجلسة رمز موقّع صالح 12 ساعة ويُلغى عند تغيير كلمة المرور أو إعادة تعيينها أو تعطيل الحساب. كل مستخدم يبدأ بكلمة مرور مؤقتة فريدة ويُلزم بتغييرها (8 أحرف على الأقل تجمع حروفاً وأرقاماً). محاولات الدخول الخاطئة المتكررة تُوقَف مؤقتاً، ولا تستهلك عمليات التخزين.
- **حدود الاستخدام**: لكل مستخدم حد للكتابة (150 طلباً في 5 دقائق) وللرفع (40 ملفاً في 10 دقائق) يمنع إغراق التخزين. الحفظ التلقائي في السحابي يجمع التعديلات المتتالية قبل إرسالها.
- **الصلاحيات على الخادم**: حساب المتابعة للاطلاع فقط؛ المهندس يقيّم ويرفق للعقود التي هو في فريقها ولا يرى مسودات زملائه (حسب إعداد الرؤية)؛ المراجع يعيد التقييم ولا يغيّر درجاته؛ الاعتماد وتغيير حالة الشركة للمعتمدين؛ المستخدمون والإعدادات والاستيراد لمدير النظام.
- **نقل بيانات الأوفلاين**: من «الإعدادات ← البيانات والنسخ الاحتياطي» يصدّر المدير نسخة من البرنامج الأوفلاين ثم يستوردها في السحابي (تُرسل مضغوطة). من غيّر كلمة مروره في الأوفلاين يدخل بها، ومن بقي على 123456 تُنشأ له كلمة مؤقتة جديدة تظهر للمدير. الاستيراد الذي يكسر الحسابات (اسم مستخدم مكرر، أو تعارض بين المعرّف والاسم) يُرفض كله دون أن يمس البيانات.

## خطة Vercel
الخطة المجانية Hobby مخصصة للاستخدام الشخصي، وعمليات Blob فيها محدودة شهرياً؛ إن تجاوزها الاستخدام يتوقف المتجر حتى بداية الدورة التالية ويعرض البرنامج رسالة واضحة. راقب الاستهلاك من لوحة Vercel ← Storage ← Usage. للاستخدام الرسمي الدائم تناسب خطة Pro.

## متغيرات البيئة على Vercel (Production فقط)
| المتغير | الغرض |
|---|---|
| `SESSION_SECRET` | مفتاح توقيع الجلسات، 32 حرفاً عشوائياً أو أكثر |
| `SEED_USERS` | قائمة المستخدمين الأولية بتجزئات كلمات المرور المؤقتة (تُستخدم مرة واحدة عند تهيئة القاعدة)، ولا تُحفظ في المستودع. تُنشأ بالأمر `node dev/make-seed.mjs app/users.local.js --out <مجلد خاص>` |
| `BLOB_READ_WRITE_TOKEN` أو `BLOB_STORE_ID` | يضيفها Vercel عند ربط متجر Blob خاص بالمشروع |
| `SELFTEST_KEY` | اختياري ومؤقت: يفعّل فحص `api/selftest?key=…` على المنصة نفسها، ويُحذف بعد الفحص |

## النشر على Vercel يدوياً (إن لزم)
1. vercel.com ← Add New ← Project ← استيراد المستودع `MohaQa5544/darafoxhills`.
2. Root Directory: `contractor-evaluation/app`، وFramework Preset: Other، بلا أمر بناء.
3. Settings ← Git ← Production Branch: الفرع الذي يحمل هذه النسخة.
4. Storage ← Create ← Blob بخيار Private، ثم ربطه بالمشروع.
5. Settings ← Environment Variables (Production فقط): `SESSION_SECRET` و`SEED_USERS`.
6. Settings ← Deployment Protection ← Vercel Authentication: Only Preview Deployments، حتى يفتح رابط الإنتاج للموظفين دون حساب Vercel.
7. Deployments ← Redeploy، ثم افتح `‎/api/health` وتأكد أن `configured` تساوي `true`.

## التشغيل والاختبار محلياً
```
cd app && npm install && cd ..
node dev/server.mjs --port 8787 --data /tmp/ev-data --reset --instances 2
node test/api-cloud.mjs      # 53 اختباراً للخادم والصلاحيات والأمان
node test/server-races.mjs   # أعطال التزامن والتخزين على منطق الخادم نفسه (رد مفقود، ذاكرة قديمة، استعادة نسخة…)
node test/e2e-cloud.js       # المتصفح كاملاً على النسخة السحابية، مع أعطال مقصودة في الشبكة والخادم
node test/e2e.js             # النسخة الأوفلاين
```
